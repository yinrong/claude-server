# 设计：手机本地客户端 + 统一接口层

## 需求背景

用户需要随时通过手机：
- **监督** AI 工作进展（查看各 Worker 状态、输出）
- **推进** AI 工作（发送指令、选择方案、确认操作）
- **审查** AI 工作结果（查看代码变更、文件、diff）

当前 Web UI 受限于浏览器能力（推送通知弱、后台刷新受限、无法常驻），需要本地客户端。

## 方案设计

### 架构

```
┌─────────────────────────┐
│   手机本地客户端 (App)    │
│  - 常驻后台              │
│  - Push 通知(Agent等待)  │
│  - 快速操作面板          │
│  - 离线消息队列          │
└──────────┬──────────────┘
           │ HTTP/WS
┌──────────▼──────────────┐
│   统一接口层             │
│  /api/v2/...            │
│  - 标准化请求/响应格式   │
│  - 认证(token)          │
│  - 版本兼容             │
│  - 事件订阅(SSE/WS)    │
└──────────┬──────────────┘
           │
┌──────────▼──────────────┐
│   claude-server          │
│  (现有 agent-manager)    │
└─────────────────────────┘
```

### 统一接口层设计要点

1. **RESTful + WebSocket 双通道**
   - REST：CRUD 操作、查询
   - WS：实时流（stream_text、status 变化、通知）

2. **标准化响应格式**
   ```json
   { "ok": true, "data": {...}, "error": null, "ts": 1234567890 }
   ```

3. **认证**
   - Bearer token（简单 API key，存在客户端本地）
   - 可选：设备绑定

4. **事件订阅**
   - `subscribe(agentId[])` — 订阅多个 agent 的状态变化
   - 事件类型：`waiting_for_input`、`output_chunk`、`task_complete`、`error`

5. **离线友好**
   - 客户端缓存最近 N 条消息
   - 请求带 `since_ts` 参数，服务端返回增量

### 手机客户端功能

| 功能 | 说明 | 优先级 |
|------|------|--------|
| Agent 列表 + 状态 | 显示所有 Agent，⏳/●/○ 状态 | P0 |
| Push 通知 | Agent 等待输入时推送到手机 | P0 |
| 快速回复 | 通知里直接输入文字回复 | P0 |
| 对话查看 | 查看完整对话历史 | P1 |
| 文件浏览 | 浏览/查看 Agent 工作目录的文件 | P1 |
| Diff 查看 | 查看 Agent 做的代码变更 | P2 |
| 批量操作 | 一键"全部继续"、批量确认 | P2 |

### 客户端技术选型（待确认）

| 方案 | 优势 | 劣势 |
|------|------|------|
| Flutter | 跨平台、原生推送、后台常驻 | 开发成本高 |
| React Native | JS 生态复用、原生推送 | 性能中等 |
| PWA + Web Push | 零安装、复用现有 UI | 后台受限、iOS 推送弱 |
| Telegram Bot | 零客户端开发、即时通知 | UI 不灵活 |
