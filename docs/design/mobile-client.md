# 设计：手机本地客户端 + 统一接口层

## 需求背景

用户需要随时通过手机：
- **监督** AI 工作进展（查看各 Worker 状态、输出）
- **推进** AI 工作（发送指令、选择方案、确认操作）
- **审查** AI 工作结果（查看代码变更、文件、diff）

## 已确认决策

| 项 | 决策 |
|----|------|
| 技术选型 | Flutter（原生体验 + 稳定后台） |
| 推送通道 | 自建 WS 长连接 + 首次启动引导用户关闭省电/后台限制 |
| 认证 | 暂不需要 |
| 多设备 | 支持多台手机同时连接 |

## 架构

```
┌─────────────────────────┐
│   Flutter App (手机)     │
│  - 常驻后台              │
│  - WS 长连接保活         │
│  - 首次引导关闭省电模式   │
│  - 多台设备同时支持       │
└──────────┬──────────────┘
           │ HTTP/WS
┌──────────▼──────────────┐
│   统一接口层  /api/v2    │
│  - 标准化请求/响应格式   │
│  - 事件订阅 (WS)        │
└──────────┬──────────────┘
           │
┌──────────▼──────────────┐
│   claude-server          │
│  (现有 agent-manager)    │
└─────────────────────────┘
```

## 统一接口层 /api/v2

### 标准化响应格式
```json
{ "ok": true, "data": {...}, "error": null, "ts": 1234567890 }
```

### WebSocket 事件订阅
- `subscribe(agentId[])` — 订阅多个 agent 的状态变化
- 事件类型：`waiting_for_input`、`output_chunk`、`task_complete`、`error`

### 离线友好
- 请求带 `since_ts` 参数，服务端返回增量

## WS 长连接保活方案

- 客户端发心跳（30s ping），服务端 pong
- 断线自动重连（指数退避）
- 首次启动弹出引导：
  - Android：引导进入"电池优化"→ 该应用"不优化"
  - iOS：说明后台刷新需开启，并告知系统限制（无法完全解决）
